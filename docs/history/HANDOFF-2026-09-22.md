## 2. 分机操作

### 2.1 【必做·各自改】MemOS 摘除

W 机的决定：**摘除**（不是继续关着）——`recall/capture/tools/viewer` 已逐个关停，插件只剩 `hostLlmEnabled` 挂名，
而 ACP 侧默认 `memosEnabled ?? true` 会**每个 pre-step 敲一次不存在的 18801**。

在各自 profile 的 `cordis.patch.yml` 改两处：

```yaml
# 1) 摘除插件（不动 package.json 的 bundles——包还在，随时可逆）
- id: memos-local-memory
  disabled: true        # ← 加这一行
  config:
    enabled: true
    …（原有配置保持不变）

# 2) ACP 侧显式声明无 recall provider（不写这行，缺省仍会构造一个默认 memos 项）
- id: adaptive-context
  config:
    …
    recallProviders: []   # ← 加这一行
```

**注意**：同 id 的 patch entry 会被后者整体覆盖（不是合并）——所有字段必须放在同一块里。
**回滚**：`disabled` 改回 false + 删掉 `recallProviders` 那行。

### 2.2 【必做·各自跑】weaver 全库转 WAL

**为什么 W 机要单独跑**：`journal_mode` 是**每个库文件自己**的属性，
而 `.tooling/scripts/kb-to-wal.mjs` 早期**写死过 A 机路径**（注释：不再写死 Administrator 的 home），
所以 2026-09-11 那次「全库转 WAL」只对当时那台机器生效。**W 机此前 11 个库全是 `delete`。**

```powershell
cd D:\DSH_workspace\.tooling
& .\bin\wv.cmd backup              # 1) 先备份（逐库 VACUUM INTO）
node .\scripts\kb-to-wal.mjs      # 2) 转 WAL（路径已派生，直接跑）
# 3) 验证：每个库 journal_mode 应为 wal；db 目录出现 <lib>.db-wal / -shm
# 4) & .\bin\wv.cmd sync-state --scan   # 应为「待同步 0 条」——换 header 不影响行级 hash
```

**预期无副作用**：`weaver-hash.mjs` 是对 `entries` **逐行**做 sha256（不是文件字节 hash），
换 journal_mode **不影响**跨机 parity 与同步。W 机实测：11 库 `delete → wal`，`sync-state --scan` 待同步 **0**。

**跨机注意（未做，待三机同步后再动）**：`wv.mjs` 的 `open()` **仍然不设** `journal_mode=WAL`，
且它的备份/播种路径用 `VACUUM INTO`——W 机实测**产物必然是 `delete` 模式**（源库是 wal、产物仍是 delete）。
所以**基线快照播种出来的新设备不会继承 WAL**。根治要改 `wv.mjs`，但它是三机共享的协议实现，先别单机改。

## 4. 已知坑与口径（W 机这一轮踩过的，别重踩）

1. **测注入面必须用真实会话的 sessionId。** 我一度用 `ledger.query(...)[0].sessionId`（随便一个会话）测 A0，
   得出「注入面几乎没变」——**结论是反的**。随便挑的会话没有同会话证据，而真实会话里同会话 `user_input` 正是填满
   `user_model` 的主力。
2. **`ledger-audit` 的 `[注入分档]` 是近似口径**：只做「窗口 + 读矩阵 + 内容去重」，**不含跨会话闸门与 section
   预算裁剪**，会高估（报 121%，`compose()` 实测 96%）。它已在输出里自标警告；看趋势可以，别当注入面真值。
3. **`apply()` 不套用 Config 的 schema 默认值**（那是宿主做的）。直调 `apply()` 的测试/脚本要么自己补齐默认值，
   要么依赖代码里的 `??` 兜底——`subagentDowngrade` 正是因此静默失效过（`9685b8e` 已补 `?? true`）。
4. **蒸馏失败率约 37%**（42 ok / 25 failed，全走云端 flash），失败文案统一是 `all routes failed`——**路由层问题，未查**。
5. **同键 observation 会 supersede**，所以「同一件事换个说法」不会自动合并；那正是 dreaming 归并（`src/dream.mjs`）要解决的。
